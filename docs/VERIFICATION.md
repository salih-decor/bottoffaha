# فحص التحقق الرسمي لنتائج Apple of Fortune على 1xBet

تاريخ الفحص: 2026-10-10 — فحص كود فقط، بدون تجاوز حماية وبدون الوصول لبيانات حساب خاصة.

## الخلاصة
- لا توجد في هذا المشروع أي واجهة رسمية موثوقة لقراءة نتائج اللعبة القادمة.
- الكود الأصلي (`app.py` + `index.html`) لا يتصل بـ 1xBet إطلاقاً: لا API، لا WebSocket، لا قراءة DOM، لا تحقق Provably Fair.
- نتائج 1xBet تتولد على السيرفر ولا تكشف مسبقاً. أي ادعاء بمعرفة الصندوق الآمن القادم بدون دليل اختباري هو ادعاء مضلل.

## ما تم فحصه
1. `app.py:calculate_smart_hash` / `generate_smart_box`: هاش محلي FNV-1a على `user_id_row_session` فقط.
2. `app.py` سابقاً: نسبة ثقة `random.randint` حسب الصف — أزيلت نهائياً في V13.
3. `index.html:analyzeNextRow`: كان `fetch` لسيرفر محلي + بديل JS يعتمد على الوقت — الآن مصنف كتجريبي فقط.
4. لا يوجد أي `fetch("https://1xbet...")` أو مفتاح API أو قراءة شاشة في المشروع.

## هل توجد آلية رسمية متاحة؟
- 1xBet لا يوفر API عاماً للاعبين يعطي نتائج الجولات القادمة أو البذور السرية مسبقاً.
- آليات Provably Fair (إن وجدت للعبة) تتيح *التحقق بعد* الجولة من أن النتيجة لم تتغير، وليس *التنبؤ قبل* الجولة.
- قراءة النتائج الظاهرة تتطلب إما إدخالاً يدوياً (المعتمد هنا) أو سكرابينج/OCR لصفحة اللعبة، وهذا:
  - غير موثوق (يتأثر بالتخطيط واللغة والتحديثات)
  - قد يخالف شروط استخدام 1xBet ويعرض الحساب للحظر
  - لا يعطي أي قدرة تنبؤية للمستقبل
  - لذلك لم يتم تنفيذه، وتم اعتماد الإدخال اليدوي بعد الظهور فقط.

## القرار المطبق في هذه المرحلة
- التسجيل يدوي: المستخدم يلعب في 1xBet، يشاهد النتيجة الفعلية، ثم يدخل `actual_box` (1-5) في `index.html` → `POST /api/rounds`.
- الإحصائيات من البيانات المسجلة فقط، مع بيان حجم العينة ومقارنة بخط أساس عشوائي 20%.
- ممنوع الادعاء بمعرفة القادم ما لم تتجاوز عينة اختبار مستقلة اختبار خط الأساس بدلالة واضحة وقابلة للتكرار.

## مراجع للتشغيل
- `rounds_store.py` للتوثيق البرمجي.
- `tests/` للاختبارات الآلية.
- تشغيل السيرفر: `python app.py` ثم فتح `index.html`.
